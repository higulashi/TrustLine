# RT1064 移植说明

目标平台为 RT1064 / MT9V034 / 编码器 / 前轮舵机。当前已完成桌面模拟，板上时延、摄像头标定和驱动接口尚未验证。MPU6050 暂未接入。

## 接口

把 `core/trustline.c` 和 `core/trustline.h` 加入工程并链接数学库。不使用堆内存、操作系统或任何厂商驱动。采用单精度浮点，允许最多 16 个路径点。扫描器中的 188 像素灰度直方图、线段中心数组是固定的栈缓冲区；实际栈用量要在所用编译器和优化选项下测量。

```c
TLState state;
TLPoint points[TL_MAX_POINTS];
tl_init(&state);

/* 在新的完整图像到达之后调用；不要和 DMA 同时读写该帧。 */
int count = tl_extract(gray_frame, 188, points);
TLCommand command = tl_step(&state, points, count,
                           encoder_speed_m_s, elapsed_seconds, TL_FULL);
/* command.steering: 弧度；command.speed: m/s。
   接入舵机标定和编码器速度闭环。 */
```

图像尺寸固定为 188×120；stride 可以大于 188，但调用者必须保证至少有 120 行有效内存。`dt` 当前允许 (0,0.2] 秒，模拟用 0.02 秒。目标板需要根据实际控制频率、曝光、图像传输与执行器时延重新设置参数。

## 首先要替换的参数

1. 替换 `tl_extract` 内的模拟行标定，建议在真实赛道上测量每条扫描行的前向距离和像素横向比例。摄像头位置改变后重新标定。
2. 测量真实轴距；代码中 0.26m 只是模拟参数。标定舵机中位、正负方向、限幅和 PWM 转换。不要直接把弧度当作 PWM。
3. 确定真实赛道宽度、边线宽度及图像阈值。扫描器目前依赖双边界，对环岛、十字、坡道和单边界没有专用处理。
4. 编码器换算为车辆实际 m/s。电机速度闭环需要在主控工程中实现；本算法给出速度建议，不输出 H 桥占空比。
5. 测量最大可用减速度、舵机响应和图像时延，再修改可见距离限速参数。IMU 当前没有接入算法，不能声称实现了陀螺仪融合。
6. 检查 DMA/cache 一致性、帧完整性和主控任务时序；它们不属于桌面算法实现。

## 验证顺序

先离线录制灰度图，核对边界提取与车辆坐标方向；然后架空车轮检查输出方向和限幅，最后在低速赛道上收集日志。桌面结果不是高速实车调参依据。

本移植方案面向带浮点支持的 RT1064，未针对 51 单片机优化。
